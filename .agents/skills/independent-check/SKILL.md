# 独立の確認

**作った本人の試験は、検収に数えません。** 同じモデルは同じ所で間違えるからです。確かめる人は、別の会社のモデルにします。

## 前提（依頼書に書いてある 4 点）

- 対象: 確かめる作業木 `.loop/work/<依頼ID>-<担い手>` と、差分の固定（`git -C <作業木> rev-parse HEAD` と `git status --short`）。測る前に同じ結果か見て、違えばそのまま報告に書く
- 期待の置き場: あなたの作業木の根の `EXPECTATIONS.md`
- 手: 実測するので `hands: workspace`
- 壊す確認: 隔離した複製で行い、終わったら戻す（対象の作業木は壊さない）

流れの中の位置は **報告 → 独立の確認（ここ）→ 指示役が `delegate.py adopt`**。

## 順番（この順番が肝）

1. **実装を読む前に**、依頼書の受け入れ条件だけを読み、`EXPECTATIONS.md` に**対**を書いて保存する。
   - 止めるべき形を最低 3 つ（入力 → 期待する結果 → なぜそう期待するか）
   - 通すべき形を最低 3 つ（同上）
   - 実装を先に見ると、「まあ、いいか」に引っ張られます。
2. 保存してから、実装と、作った人の試験を読む。
3. **自分で測る。** 作った人の試験を動かすだけでは足りません。1 で書いた対を、自分で流す。
4. **わざと壊して、試験が落ちることを見る。** 隔離した複製で 2〜3 通り壊し、終わったら戻す。落ちなければ、その試験は守っていません。
5. 合否を書いて返す。

## 返す形

```markdown
# 確認: <依頼ID>
## 合否
＜合格 / 差し戻し＞
## 先に書いた対
＜EXPECTATIONS.md の path と、対の数＞
## 実測
- ＜対の数＞ 件を流して、ずれ ＜N＞ 件
- わざと壊した ＜N＞ 通り → 落ちた ＜N＞ 通り
## 差し戻す点（差し戻しのときだけ）
- ＜何が / どこが / どう直すか＞
```

## 守り（harness/guard.py）を確かめるときの注意

あなた自身が担い手として動いていると、環境変数 `HARNESS_ROLE=worker` が付いている。この印があると守りは
「聞く」を「止める」に倒す。守りの素の判定を測るときは、印を外して流す:
`env -u HARNESS_ROLE -u HARNESS_HANDS HARNESS_ATTENDED=1 python3 harness/guard.py ...`（既定では「聞く」も止まるので、素の判定を見るには人がいる印を付ける）
（2026-09-23 の独立の確認で、この差を「ずれ」と数えた例があった）

## やってはいけないこと

- 自分で直さない（直しは、作った担い手へ差し戻す）
- 作った人の試験を「通ったから合格」としない
- 対を後から書き換えない（外れたなら、外れたと書く）
