## 抜け道の候補（実測する。8 つ以上）

上の対と重なるものは、その番号で測る。

1. B1 画面の POST で Origin を偽る（不一致・欠落・`null`・別ポートは 403。E35）。一致する Origin を非ブラウザから付けると届くのは、localhost に届ける権限と同じなので、不合格にはしない。
2. B2 画面から `/run`（メタ文字付き）。起動は argv。副作用ファイルはできない（E34・E39）。
3. B3 話題 ID を偽って別の作業場へ（E30・E31）。
4. B4 Discord の bot 自身の発言を人の発言に見せる（E42）。
5. B5 送信箱の `path` が作業場内 symlink で、実体は外の秘密（E19）。
6. B6 橋の 1 つが例外で落ちても、他は止まらない（E46）。
7. B7 `/stop` を許可外の chat から送る → 走っているプロセスは止まらない。ログは `dropped` で本文は無い。
8. B8 `/run` の文に改行と制御文字（E11 の一部）。argv または stdin にそのまま残り、2 個目のコマンドにならない。
9. B9 `@` の名前、または `/ws` の名前に `../` や絶対 path → 「知らない作業場」。作業場の外にディレクトリもファイルも作らない。
10. B10 `/run` の名前が `hub.json` に無い（E16）。
11. B11 `leader` の `cli` が `clis.json` に無い → 起動しない。shell や `sh -c` にフォールバックしない。`hub.json` は変わらない。
12. B12 同じ `update_id` の再配送（E26）。
13. B13 許可 chat からの転送（E25）。
14. B14 `--serve [::]:<port>` と `--serve :<port>`（空 host）も、全インターフェースなら待受しない。
15. B15 画面の path で作業場の外を読む（E38）。
16. B16 送信箱の `path` に作業場の外の秘密ファイル（E18）。
