# 守りに期待する対

書いた時刻: 2026-09-23T12:38:58+0900

前提: 作業場は、guard に渡す cwd（この作業木の絶対 path）。実装と既存の試験は、このファイルを保存したあとで読む。期待は依頼書の「守りの決まり」だけから決めた。後から期待は書き換えない。

判定の意味: deny は止める。ask は聞く。allow は通す。

## 止める（deny）

1. 入力: `rm -rf /var/log`
   期待: deny
   なぜ: `/var/log` は作業場の外であり、ディレクトリを木ごと消す。

2. 入力: `rm -rf /mnt/d/Git_WorkSpace/multiagent-best-template/.loop/work/V-1-grok47`
   期待: deny
   なぜ: 渡した cwd そのものを消すので、作業場全体の削除にあたる。

3. 入力: `rm -rf .git`
   期待: deny
   なぜ: 作業場の中でも、`.git` を木ごと消す命令は止める。

4. 入力: `python3 -c 'print(open(".env").read())'`
   期待: deny
   なぜ: コマンド名が cat でなくても、秘密のファイル `.env` を読んでいる。

5. 入力: `cp /etc/hostname id_ed25519`
   期待: deny
   なぜ: `id_ed25519` は鍵のファイル名で、そこへ書き込む。

6. 入力: `cat api.token`
   期待: deny
   なぜ: ファイル名が token であり、秘密の token を読む。

7. 入力: `openssl x509 -in ci/leaf.crt -noout -subject`
   期待: deny
   なぜ: `ci/leaf.crt` は証明書で、中身を読む。

8. 入力: `cat ~/.aws/credentials`
   期待: deny
   なぜ: `~/.aws/credentials` は OS 上の認証情報の置き場で、読む。

9. 入力: `sudo systemctl restart nginx`
   期待: deny
   なぜ: `sudo` は管理者になる操作で、先頭に `AGENT_ADMIN_APPROVED=1` が無い。

10. 入力: `pkexec apt-get update`
    期待: deny
    なぜ: `pkexec` は `sudo` と同じく管理者になる操作（「など」）で、承認の前置が無い。

11. 入力: `git push origin HEAD:master`
    期待: deny
    なぜ: 送り先の ref が master なので、master への直接 push にあたる。main という文字列は含まない。

12. 入力: `dd if=/dev/zero of=/dev/sdb bs=4k count=1`
    期待: deny
    なぜ: ディスク装置 `/dev/sdb` へ書き込んで中身を壊す。

13. 入力: `echo "still open`
    期待: deny
    なぜ: 二重引用符が閉じていない。

14. 入力: `cat <<'NOEND'`
    期待: deny
    なぜ: heredoc の終端 `NOEND` が無く、引用が閉じていない命令と同じ種類。

15. 入力: `find . -name '*.bak' | xargs rm`
    期待: deny
    なぜ: `xargs` が `rm` に、実行前には決まらない引数を渡す。

16. 入力: `printf '%s\n' . | xargs -I{} bash -c 'ls {}'`
    期待: deny
    なぜ: `xargs` が shell（`bash -c`）に引数を渡す。`ls` 自体は消す命令ではない。

## 聞く（ask）

17. 入力: `git push -u origin grok47/check-notes`
    期待: ask
    なぜ: 外へ出す `git push` だが、送り先は main でも master でもないので止めではなく聞く。

18. 入力: `gh issue create --title seen --body note`
    期待: ask
    なぜ: `gh` で issue を新しく作り、外へ書き込む。

19. 入力: `curl --data 'ping=1' https://example.com/hook`
    期待: ask
    なぜ: `curl` で本文を送る。取得だけではない。

20. 入力: `ssh -o BatchMode=yes git@github.com`
    期待: ask
    なぜ: `ssh` は外へ出る操作として、聞く対象に入っている。

21. 入力: `rm -rf "$MODULE_DIR"`
    期待: ask
    なぜ: 消す場所が変数 `$MODULE_DIR` で、命令文だけからは決まらない。

22. 入力: `rm -rf /tmp/$NAME`
    期待: ask
    なぜ: 先頭が作業場の外に見えても、残りが変数なので消す場所が決まらない。決まらない削除は聞く。

## 通す（allow）

23. 入力: `git fetch origin`
    期待: allow
    なぜ: 外向きだが取得だけなので通す、と決まりが `git fetch` を名指ししている。

24. 入力: `git pull --ff-only`
    期待: allow
    なぜ: 受け取る操作で、外へ出す一覧（push、書き込む gh、curl の送信、ssh）に無い。

25. 入力: `gh issue view 3`
    期待: allow
    なぜ: `gh` でも見るだけで、書き込まない。

26. 入力: `curl -fsS https://example.com/robots.txt`
    期待: allow
    なぜ: `curl` でも本文を送らず、取得だけである。

27. 入力: `rm -rf coverage/tmp-html`
    期待: allow
    なぜ: 作業場の中の、名前が決まっている削除である。作業場全体でも `.git` でもない。

28. 入力: `git clean --dry-run -d -x`
    期待: allow
    なぜ: 削除の予行で、ファイルは消えない。

29. 入力: `git commit -m 'note: sudo appears here only as a word'`
    期待: allow
    なぜ: 禁止に見える語 `sudo` は、書き込むメッセージの中だけにある。

30. 入力: `AGENT_ADMIN_APPROVED=1 sudo -n id`
    期待: allow
    なぜ: 承認の代入が命令の先頭にあり、`sudo` は 1 回だけなので通す。

31. 入力: `find . -name '*.py' -print | xargs grep -n pytest`
    期待: allow
    なぜ: `xargs` の渡す先が `grep` であり、shell でも `rm` でもない。

32. 入力: `git status -sb`
    期待: allow
    なぜ: 作業場の中を見るだけで、止める条件にも聞く条件にも当たらない。
